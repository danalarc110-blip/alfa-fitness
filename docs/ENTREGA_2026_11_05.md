## Reglas del negocio que deben conservarse

- Cada entrada de una persona sin membresía vigente cuesta **USD 2.00**, confirmados en recepción por Secretaría o Administración. No es un pase para todo el día.
- La membresía vigente incluye el acceso durante todo su último día. Las cuentas inactivas y las membresías en pausa conservan sus bloqueos.
- La salida no cobra. Reenviar la misma entrada no duplica asistencia ni pago. Volver a ingresar después de salir requiere una nueva entrada y, sin membresía vigente, otros USD 2.00.
- No se crean cobros para las visitas históricas. Los pagos reales de entrada quedan vinculados a la asistencia y al empleado que los confirmó.
- Los resúmenes financieros y la gráfica de Inicio son exclusivos del administrador. Secretaría conserva los importes individuales necesarios para operar. Las sesiones simultáneas de cliente y empleado no deben conceder al cliente permisos financieros.
- Los informes muestran **ingresos cobrados**, no ganancias netas. El sistema no registra costes ni gastos.

## Preparar y comprobar

Sigue los requisitos del README. En una instalación existente, conserva `APP_KEY`, respalda los datos y aplica únicamente las migraciones pendientes. Las bases de prueba y sus contraseñas aleatorias no se versionan.

```sh
composer install
npm ci
php artisan migrate
npm run build
php -d extension=zip vendor/bin/phpunit
php artisan view:cache
php vendor/bin/pint --test app bootstrap/app.php bootstrap/providers.php config database routes tests tools lang
node tools/frontend_regression_check.cjs
node tools/appearance_regression_check.cjs
node tools/training_edge_check.cjs
```

El parámetro `-d extension=zip` corresponde al XAMPP de la máquina donde se revisó; omítelo si ZIP ya está habilitado. PHPUnit usa SQLite en memoria. No uses `migrate:fresh` sobre una instalación con datos que deban conservarse.

La última revisión funcional completa ejecutó **390 casos y 2918 aserciones sin errores ni fallos**, con dos integraciones PostgreSQL omitidas por falta de conexión de prueba externa. También pasaron 10 grupos de regresión del frontend, 4 de apariencia y 4 controles del entrenamiento, además de los recorridos reales de Chrome a 1440 y 390 píxeles. Las pruebas en navegador móvil son emuladas, no una prueba en un teléfono físico.

Las herramientas `prepare_review_qa.php` y los runners de revisión generan o consumen bases SQLite temporales y archivos privados en `storage/app/private`. No incluyen credenciales fijas. Los runners de navegador de esta máquina usan Chrome y PHP de XAMPP en rutas Windows; adapta esas rutas antes de usarlos en otro equipo. Los scripts de capturas son auxiliares de QA, no parte del servidor de producción.

## Pendientes y límites de producción

- **Integración y despliegue:** el servicio de Render sigue conectado a `main`. La última comprobación de producción encontró el despliegue `86d3cbd` activo, `/up` con HTTP 200 y sin errores en las últimas 24 horas consultadas. Esta es una observación del 5 de noviembre, no una garantía continua. Verifica de nuevo los cuatro roles, los cobros, los informes y `/up` después de integrar y publicar.
- **PostgreSQL:** la base gratuita observada vence el **27 de noviembre de 2026 a las 21:53, hora de El Salvador**. Resuelve su continuidad y conserva un respaldo antes de ese plazo. Las dos pruebas PostgreSQL pendientes requieren una base externa de pruebas; no deben apuntar a producción.
- **Correo:** el transporte conocido `log` no entrega mensajes. Configura y prueba SMTP real para invitaciones y recuperación. No se verificó entrega real ni se incluyeron secretos en esta entrega.
- **Archivos subidos:** el plan gratuito de Render tiene almacenamiento efímero para imágenes nuevas; la guía de Render explica sus límites y los archivos iniciales recuperables.
- **Pruebas externas:** no se hizo una prueba de carga ni se verificaron credenciales reales de Google o acceso autenticado de los cuatro roles en producción con esta nueva versión.
